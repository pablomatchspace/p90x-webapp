# Epic E33 — P90X Generation Next program

> **Status:** delivered · **Stories:** US-160 → US-166
> **Ships as:** package **1.33.160**…**1.33.166**, displayed **`1.E33.U160`**…`U166` · **Schema:** **v13 → v14** (`program` becomes `{ suite, variant }`; exercise entries allow 5 rounds)
> **One-liner:** Start (or start the next round as) **P90X Generation Next** — BODi's
> 2026 90-day program with Waz Ashayer — next to Classic and Lean: its own
> 90-day calendar, its 14 workouts and 5 bonus "fivers", dumbbell logging by
> block with 5-round finishers, all scored by the existing Classic engine.

---

## 1. Problem

The app runs exactly one catalog — the P90Xcel workbook's — with two schedule
variants (Classic, Lean). A user who finishes a Classic round and moves on to
Generation Next has to leave the app: there is no way to pick another program,
its workouts are not in the catalog, and its dumbbell tracker (weight per
round, Block 1 / Block 2 / Finisher, up to 5 finisher rounds) does not fit
the 4-round logging limit.

## 2. Goals

1. **Pick a program suite, then a variant** on the `/start` screen and when
   starting the next round: `p90x` → Classic / Lean, `gennext` → Standard.
2. **Generation Next data** — 90-day template + catalog generated by
   `tools/gen_gennext.py` from the oracle doc
   [`docs/requirements/gennext-workouts.md`](../requirements/gennext-workouts.md)
   (video-derived, cross-checked against the BODi calendar and Dumbbell Tracker
   PDFs). `src/data` stays generated, never hand-edited (CLAUDE.md layout).
3. **Log the dumbbell workouts like the tracker** — reps + weight per round,
   grouped by block, finisher up to 5 rounds; everything else is
   completion-style (done / not done).
4. **Score with the Classic engine** (decision **D9**).
5. **Bonus 5-minute workouts** as optional add-ons on any Generation Next day —
   done/not done, never counted in adherence.
6. **Lock the program once a round starts** — changing it means completing
   (archiving) or deleting the round on Rounds; comparisons only pair rounds of
   the same suite.

## 3. Non-goals

- **Focus/Play timelines** for Generation Next workouts — E34.
- **Portion Fix nutrition** — E35 (blocked on BODi's container-plan PDFs);
  Generation Next rounds keep the existing nutrition targets meanwhile.
- P90X Plus / P90X2 / P90X3 (RQ-008 lists them; out of scope here).
- Committing any copyrighted material: the oracle doc paraphrases facts with
  `mm:ss` evidence, never transcript quotes or frames.

## 4. Design

### 4.1 Program model (US-160)

- `ProgramSuite = 'p90x' | 'gennext'`, `ProgramVariant = 'classic' | 'lean' | 'standard'`,
  `ProgramRef = { suite, variant }` replaces `ProgramKey`. The persisted field
  keeps its name — `settings.program` and `archivedRounds[].program` — but now
  holds a `ProgramRef` (AUTO-DECISION, see §8: same suite/variant model as the
  plan, far less churn than two flat fields).
- `PROGRAMS` registry: suite → label, variants, template. `getTemplate(ref)`,
  `programLabel(ref)` (`'Classic'`, `'Lean'`, `'Generation Next'`),
  `workoutsFor(suite)`, `loggableWorkoutsFor(suite)`. `getWorkout(key)` stays
  global — Generation Next keys are prefixed `gn-`, so keys never collide.
- **Schema v14** (`MIGRATIONS[13]`): `program: 'classic' | 'lean'` →
  `{ suite: 'p90x', variant }`, in settings and every archived round;
  `exerciseEntry.rounds` max 4 → 5. Old backups restore as `{ p90x, classic|lean }`.

### 4.2 Data (US-161)

- `tools/gen_gennext.py` holds the structured source (transcribed from the
  oracle doc) and writes `src/data/gennext.json` = `{ workouts, template }`.
  `verify()` pins all 90 calendar cells and the 7 tracker exercise lists.
- `CatalogExercise.block?: 'Block 1' | 'Block 2' | 'Finisher'`,
  `WorkoutDef.pillar?: 'MOT' | 'NPT' | 'ART'`, new style `'bonus'`.
- Recovery weeks 4, 8, 13 (`recovery: true`); all 90 days required —
  Myofascial Release counts toward adherence like any workout. Week 13 has
  6 days (Sunday blank) → 90 days total.

### 4.3 Logging & scoring (US-162) — decision D9

Dumbbell exercises use `secondary: 'weight'`; each round scores R×W/rwDivisor,
averaged over rounds (Classic engine, unchanged). The 2-round drop penalty
only applies when an exercise has exactly 2 rounds, so it never fires for
Generation Next (3 or 5 rounds). The logging grid groups rows by `block`.

### 4.4 Start, lock & Rounds (US-163)

- `/start`: suite chooser, then variant; Generation Next shows its day-1
  workout, pillars and equipment.
- Settings: program read-only while a round runs — card "A round is in
  progress. Complete or delete it on Rounds to start another program." with a
  link to `/rounds` (RQ-008 Scenario A). The Classic↔Lean switch is removed
  (amends D8: the Lean toggle now lives on `/start`).
- Round comparison candidates are filtered to the same suite.

### 4.5 Program-agnostic copy (US-164) & bonus add-ons (US-165)

- Labels via `programLabel(ref)`; WorkoutsPage groups Generation Next by
  pillar; X Stretch rest-day play only for `p90x`.
- "Add a 5-min bonus" on Today / day detail creates a completion session under
  the bonus key with the day's `programDayId`; status and adherence ignore
  `style: 'bonus'`.

## 5. Stories

### US-160 — Suite/variant model + schema v14 (M, P0)
- AC1 `ProgramRef` replaces `ProgramKey`; `getTemplate`, `materialize`, `beginProgram`,
  archive/restore, overload fallback, round report/compare, import summary take it.
- AC2 v13 documents (settings and archived rounds) migrate to `{ suite: 'p90x', variant }`;
  fixtures v1…v14 load with no unmapped keys; a v14 fixture is committed.
- AC3 Exercise entries accept 5 rounds.

### US-161 — Generation Next data generator (M, P0)
- AC1 `src/data/gennext.json` is generated, never hand-edited; `verify()` passes.
- AC2 Golden master: day 1 = Push Strength; week 6 Wednesday = Push Strength;
  week 13 has 6 days; recovery = weeks 4, 8, 13; 90 days.
- AC3 The 7 dumbbell workouts match the Dumbbell Tracker (names, blocks, order, rounds).

### US-162 — Logging + scoring (M, P0)
- AC1 Strength-style rows score R×W/rwDivisor averaged over 3 or 5 rounds; penalty 0.
- AC2 Logging grid groups by block; finisher rows show 5 rounds where the tracker does.
- AC3 Myofascial Release is a required day for status/adherence.

### US-163 — Start, Rounds & lock (M, P0)
- AC1 `/start` picks suite then variant; starting Generation Next materializes its template.
- AC2 Settings shows the program read-only with the Rounds link while a round runs.
- AC3 Compare lists only same-suite archived rounds.

### US-164 — Program-agnostic UI copy (S, P1)
- AC1 No hardcoded Classic/Lean labels remain; pillars group Generation Next workouts.

### US-165 — Bonus add-ons (S, P1)
- AC1 A bonus can be attached to any Generation Next day and marked done.
- AC2 Bonus sessions never change day status or adherence.

### US-166 — E2E, baselines & release (S, P1)
- AC1 `e2e/gennext.spec.ts` (desktop + realme): start Generation Next → log Push
  Strength incl. a 5-round finisher → bonus → complete round → start Classic; lock test.
- AC2 win32 + linux visual baselines regenerated; `1.33.166`, CHANGELOG `1.E33.U166`.
