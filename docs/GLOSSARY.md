# Glossary — ubiquitous language

The single vocabulary for this app. Terms come from the P90X workbook
(`P90Xcel v2.05`, the oracle — CLAUDE.md rule 1); each row maps the workbook
term to its schema/code identifiers so conversation, docs, code and tests all
use the same words. When adding code, use these terms — if a concept isn't
here, add it in the same PR that introduces it.

Bounded-context column refers to [`docs/CONTEXT-MAP.md`](CONTEXT-MAP.md).

## Program & schedule (context: schedule)

| Term        | In code                                      | Meaning                                                                                                                                                                       |
| ----------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Program     | `settings.program` (`'classic' \| 'lean'`)   | Which 90-day P90X variant is being followed. A program exists exactly when `settings.startDate` is non-null.                                                                  |
| Round       | `ArchivedRound`, `archivedRounds[]`          | One full 90-day run of a program. Completed rounds are archived (raw inputs + a frozen SETUP snapshot); the current round is the live state. Distinct from an exercise round. |
| Program day | `ProgramDay`, `programDayId` (`d001`–`d090`) | One of the 90 template slots. Logs attach to the slot id, so they travel with the slot when rescheduled.                                                                      |
| Schedule    | `materialize(program, startDate, ops)`       | The calendar mapping of program days to dates. Never stored — always recomputed from the start date and the op log (rule 2).                                                  |
| Start date  | `settings.startDate`                         | Local-calendar ISO date of day 1. `startProgram` sets it once; moving it afterwards is `setStartDate` (guarded by a confirm).                                                 |
| Schedule op | `ScheduleOp` (`skip` / `swap` / `remap`)     | An append-only reschedule event. Reverted ops stay in the list for the audit trail (`revertedAt`) but are ignored when materializing.                                         |
| Gap day     | `GapDay`                                     | A calendar day the schedule skips over (created by `skip` ops) — no program day lands on it.                                                                                  |
| Week        | `fromWeek`, `WeekSection`                    | One of the 13 program weeks (7 slots each). `remap` permutes slot order within remaining weeks.                                                                               |
| Adherence   | `computeAdherence`, `Adherence`              | Derived done/missed/pace statistics over the materialized schedule and session index. Never stored.                                                                           |
| Day status  | `DayStatus`                                  | Derived per-day state: `gap · rest · done · partial · missed · pending`.                                                                                                      |

## Workout logging & playback (context: workouts)

| Term            | In code                                               | Meaning                                                                                                                                                   |
| --------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workout         | catalog key, e.g. `chestBack` (`getWorkout`)          | One of the named P90X routines from the workbook catalog. Reference data, generated by `tools/` — never hand-edited.                                      |
| Session         | `Session`                                             | One logged performance of a workout on a program day. One session per (workout, program day); repeat edits update it in place.                            |
| Exercise        | catalog `exercises[]`, `exerciseId`                   | One movement inside a strength/ARX workout (e.g. Standard Push-Ups).                                                                                      |
| Exercise round  | `ExerciseRound` (`exerciseRoundSchema`)               | One attempt column for an exercise — round 1, round 2 (Strip-Set Curls has 4). The workbook's paired entry cells. Distinct from a 90-day round.           |
| Reps / assist   | `ExerciseRound.reps` / `.assist`                      | The raw pair per exercise round: reps / assisted (knee-chair) reps for rep rows; reps / weight for R×W rows; count / other-side count for two-sided rows. |
| R×W             | `rw` row type                                         | Reps-times-weight exercise rows; charted as `reps × weight ÷ rwDivisor` (SETUP!C49).                                                                      |
| Completed?      | `Session.completion` (`yes / no / not-yet`)           | The Excel COMPLETED? dropdown on cardio-style sheets. Strength/ARX sessions use the boolean `completed` instead.                                          |
| Score           | `scoreExercise`, `sessionTotals`                      | Derived workbook score for an exercise/session, penalty included. Never stored.                                                                           |
| Penalty         | `penaltyDivisor` (SETUP!C44), `penaltyOn` (SETUP!C45) | Round-1→2 drop penalty: the drop divided by the divisor, subtracted when enabled. Canonical rule B3 (PRD §6.4) is the one documented workbook deviation.  |
| Chair factor    | `chairFactor` (SETUP!C47)                             | Chair-assisted / knee reps count as `1/factor` of a rep.                                                                                                  |
| Focus steps     | `focusSteps`                                          | The derived play-mode step list (exercise → rest → …) for a session.                                                                                      |
| Timeline        | `timelines/*`                                         | The fixed segment list of an interval workout (Cardio X, Kenpo X, …) used by play mode.                                                                   |
| Progression     | `progression`                                         | Derived exercise history across occurrences of a workout — the strength-progress charts.                                                                  |
| Overload target | `overload`                                            | Derived progressive-overload suggestion for the next session (E29).                                                                                       |
| Voice entry     | `voiceEntry`                                          | Parsing spoken reps/weight into raw entry values (E30). Only the parsed numbers are stored.                                                               |

## Body & setup (context: body)

| Term         | In code                                  | Meaning                                                                                                           |
| ------------ | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Body entry   | `BodyEntry`, `bodyLog[]`                 | One scale reading per date: weight, body-fat, water, bone, zone minutes. Missing days stay missing (honest gaps). |
| SETUP inputs | `settings` (age, height, startWeight, …) | The workbook SETUP sheet's raw inputs. Canonical storage is metric: meters / kg / body-fat fraction 0–1.          |
| Limits       | `settings.limits`                        | SETUP warning thresholds (weight / body-fat / BMI) — drive warnings, never block input.                           |
| Targets      | `settings.targets`                       | SETUP goals: lean-mass increase, body-fat, FFMI.                                                                  |
| BMI / FFMI   | `body.ts`, `ffmi.ts`                     | Derived body metrics per workbook formulas. Never stored.                                                         |
| Body fat     | `bodyFat.ts`                             | Derived estimates (Navy et al. calculators) — inputs raw, results derived.                                        |
| Feasibility  | `feasibility.ts`                         | Whether the lean-mass target is achievable at the experience tier's rate (`settings.training`, E20).              |
| Snapshot     | `RoundSnapshot`                          | The round-scoped SETUP inputs frozen at archive time, so later Settings edits never rewrite history (E28).        |

## Cloud sync (context: sync)

| Term       | In code                     | Meaning                                                                                                                                |
| ---------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Sync       | `sync.ts`, `state/sync*.ts` | Opt-in E2E-encrypted replication of the document to a user-hosted backend (E10). Off by default; zero network calls when off.          |
| Passphrase | never persisted             | User secret deriving the AES key. The non-extractable key + auth token live in IndexedDB (`state/syncSecrets.ts`), never localStorage. |

## Document & shared kernel (context: shared)

| Term                | In code                                            | Meaning                                                                                                                                                                                                                                        |
| ------------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Document            | `AppState`, `appStateSchema`                       | The single versioned persisted JSON document. Raw inputs only — every derived number is a pure function.                                                                                                                                       |
| Schema version      | `SCHEMA_VERSION`, `migrations.ts`                  | Document shape version; old/corrupt documents migrate or degrade to a clean empty state with a recovery offer.                                                                                                                                 |
| ISO date            | `ISODate`, `isoDate`                               | Local-calendar `YYYY-MM-DD` string. Never `Date` UTC arithmetic (rule 5).                                                                                                                                                                      |
| Canonical units     | `Kg`, `Meters`, `BodyFraction` (`shared/units.ts`) | Branded types for the canonical metric storage (kg / meters / 0–1 composition fraction, the latter covering body fat, water and bone). Compile-time only; constructed at the conversion boundary (`unitToKg`, `unitToM`, `percentToFraction`). |
| Catalog / templates | `programData.ts` (`src/data/*.json`)               | Workbook-generated reference data: program templates (which workout on which day) and the workout catalog (exercises, row types, rounds). A published language shared by all contexts.                                                         |
| Quote               | `quotes.ts`, `customQuoteSchema`                   | Motivational quotes; built-ins unattributed unless verifiable (rule 4).                                                                                                                                                                        |
| Import/export       | `importExport.ts`                                  | Zod-validated document round-trip — the anti-corruption layer for anything entering state.                                                                                                                                                     |

## Terms that sound alike (watch out)

- **Round** (90-day program run, `ArchivedRound`) vs **exercise round**
  (`ExerciseRound`, an attempt column within an exercise). Say "exercise round"
  whenever there is any chance of confusion.
- **Session** (one logged workout performance) vs **workout** (the catalog
  routine itself). `workoutLogs[workoutKey].sessions[]` holds sessions.
- **completed** (strength/ARX boolean) vs **completion** (cardio `yes/no/not-yet`
  dropdown). `workoutState` in `schedule/status.ts` folds both into one derived
  `WorkoutState`.
- **reps/assist**: `assist` changes meaning by row type (assisted reps, R×W
  weight, or other-side count — see table above); the pair is the workbook's
  raw cell duo. Distinct from the catalog's `exercise.secondary`, which names
  the row _kind_ (`knee/chair/weight/extra`) in generated reference data.
